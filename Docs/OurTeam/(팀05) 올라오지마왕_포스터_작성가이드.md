## 레퍼런스 포스터가 채운 방식 (요약)

학교 샘플 3종은 공고 6축 제목을 그대로 쓰지 않고, **학술 포스터 섹션 + 그림 캡션 + 번호 소절(3.1, 3.2…)** 로 내용을 채웁니다.

| 레퍼런스 | 주요 섹션 | 본문 특징 | 그림 배치 |
|----------|-----------|-----------|-----------|
| **Crossy Code** | Objectives → Methodology(3.1~3.4) → Conclusion | 교육 목적·문제 제기 후 **기능별 서술** | 스타트/챕터 UI, 블록 예시, 튜토리얼·클리어 |
| **트리런** | Abstract → Feature(3.1~3.4) → Rule → Graphics & Design → Reference | **스토리+장르+조작**을 Abstract 한 덩어리로, Feature에서 차별점 | 메인·플레이 화면, 나무 오브젝트, 규칙 시연 스트립 |
| **Foresight** | Abstract → Feature(3.1~3.3) → Rule → Graphics & Design → Reference | 핵심 메카닉(예지·마킹)을 Feature 소절로 분리 | 스테이지 선택, 플레이, NPC·마커 비교 |

**공통 패턴**

1. **상단** — 게임 제목 + 한 줄 부제(장르·대상)  
2. **Abstract(또는 Objectives)** — 세계관·승패·플랫폼·한 판 루프를 **3~6문장 연속 서술** (불릿 나열 X)  
3. **Feature / Methodology** — `3.1`, `3.2` … 소제목 + **완전 문장** 2~4문장 + 옆/아래 **그림 N**  
4. **Rule(또는 Conclusion)** — 조작·클리어 조건·점수/별 등 **규칙**을 짧게  
5. **Graphics & Design** — 픽셀 아트·UI·음향 컨셉 (직접 제작 vs 에셋 구분)  
6. **Reference** — 외부 에셋·사이트 링크 (있을 때만)  
7. **하단** — `Department of Digital Media, Ajou University` + 팀 메일 + `Professor 오규환 / drghoh@ajou.ac.kr`

> **공고 6축**은 아래 [섹션 매핑]표처럼 위 섹션에 **흡수**해 넣습니다. 템플릿 칸 이름이 다르면 내용만 맞추면 됩니다.

## 포스터 본문 초안 (섹션별 · 복사 후 다듬기)

### Abstract

올라오지마왕은 Donkey Kong에서 영감을 받은 **역할 전환형 2D 수직 클라이머**로, 플레이어는 화면에 직접 나타나지 않고 화면 상단에서 장애물을 떨어뜨려 탑을 오르는 용사를 막습니다. 용사는 Unity ML-Agents로 학습한 신경망이 이동과 점프를 결정하며, 플랫폼을 오르고 낙하·튕김·구름 장애물과 바닥에서 올라오는 용암을 동시에 피해 목표 높이에 도달하려 합니다. 용사의 체력을 모두 소진하면 플레이어가 승리하고, 용사가 목표에 도달하면 패배합니다. 플랫폼은 PC(1920×1080 윈도우 빌드)이며, 인트로 스토리와 메인 메뉴를 거쳐 세 단계 스테이지를 플레이합니다. 스테이지마다 무작위로 이어 붙인 타워 맵이 생성되어 반복 플레이 때마다 경로가 달라집니다.

### Feature

**3.1. ML-Agents 클라이머 AI**  
본 프로젝트는 PPO 알고리즘으로 클라이머 정책을 학습한 뒤 ONNX로 빌드에 탑재해 **추론만** 수행합니다. 클라이머는 8차원 정규화 관측과 Ray Perception, 지상·공중·피격 상태 머신으로 판단하며, 학습 시에는 휴리스틱 스포너 봇이 플레이어 대신 장애물을 의도적으로 배치합니다. Lv1~3 난이도는 별도 규칙 AI가 아니라 **학습 체크포인트 ONNX 교체**로 조절합니다.  
→ *그림 2: Behavior Parameters 또는 아키텍처 다이어그램*

**3.2. 장애물 3종과 물리**  
Faller는 수직 낙하, Bouncer는 좌우 벽 반사, Roller는 발판을 따라 구르는 Donkey Kong식 Barrel 물리를 수동 kinematic과 CircleCast로 구현했습니다. 종류별 속도와 스폰 쿨다운은 `ObstacleTuningConfig` ScriptableObject로 분리합니다.  
→ *그림 3~5: 세 종 Preview·플레이 스샷 스트립*

**3.3. UI·동적 맵·연출**  
`MapGenerator`가 에피소드마다 타워를 재생성하고, Height Bar·HP Bar·스킬바로 전투 상황을 표시합니다. 결과 화면은 DOTween으로 팝업·별·통계를 연출하며, `timeScale=0` 상태에서도 UI 애니메이션이 동작합니다.  
→ *그림 1: 인게임 전체 / 그림 6: 승리 결과 UI*

**3.4. 메타 진행 (재화·업그레이드)**  
클리어 시 플레이 시간과 스폰 횟수로 점수를 산출해 재화로 적립하고, 별 등급과 레벨 진행은 `PlayerPrefs`에 저장합니다. 메인 메뉴 업그레이드에서 Faller·Bouncer·Roller 트리를 강화하면 다음 판부터 해당 장애물의 속도가 오르고 쿨다운이 줄어듭니다. 스테이지 난이도(ONNX)와 플레이어 성장(업그레이드)을 분리한 **2축 설계**입니다.  
→ *그림 7: Upgrade 팝업*

**3.5. 생성형 AI 활용 (공고 필수)**  
기획 단계에서는 ChatGPT·Gemini로 메카닉 초안을 보조했고, Ludo.ai 등으로 픽셀 에셋 초안을 만든 뒤 Pixel Studio·Photoshop에서 수정했습니다. 구현 단계에서는 Cursor로 C# 작성·리팩터링을 지원받았으며, 결과물은 팀이 검수·통합했습니다.

### Rule

마우스 왼쪽 클릭으로 클릭 위치에 Faller·Roller를 스폰하고, Bouncer는 클릭 후 드래그 방향으로 발사합니다. 키보드 1·2·3으로 장애물 종류를 바꾸며, 쿨다운이 끝나기 전에는 스폰되지 않습니다. 스폰 전 점선·화살표로 궤적을 미리 보여 줍니다. 승리 시 플레이 타임·스폰·명중 통계가 표시되고, 플레이타임·스폰 횟수로 합산한 점수에 따라 별(최대 3개)과 재화가 부여됩니다. 이전 스테이지 클리어 시 다음 레벨이 해금됩니다.

### Graphics & Design

인트로 3컷 스토리, 픽셀 아트 캐릭터·UI·맵 타일을 팀이 제작·보정했습니다. 메인·결과·업그레이드 UI는 게임 톤에 맞춘 패널과 아이콘으로 통일했으며, BGM·효과음은 Intro·Main·Play·승패·피격·스폰에 맞게 분리해 재생합니다. 발표 자료의 Slime 표기는 최종 빌드의 **Roller**로 통일합니다.
