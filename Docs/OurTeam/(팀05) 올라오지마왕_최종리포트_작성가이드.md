## 1. 프로젝트 요약 (초안)

**올라오지마왕**은 Donkey Kong에서 영감을 받은 **역할 전환형 2D 수직 클라이머**입니다. 플레이어는 화면에 직접 등장하지 않고, 화면 상단에서 쿨다운이 걸린 세 가지 장애물(Faller, Bouncer, Roller)을 배치해 아래로 올라오는 **용사(클라이머)** 를 막습니다. 용사는 Unity ML-Agents로 학습한 신경망(ONNX)이 이동·점프를 결정하며, 플랫폼을 오르고 장애물과 상승 용암을 피해 목표 지점까지 가려 합니다.

**승패 조건(플레이어 관점):** 용사의 체력을 모두 소진하면 **승리**, 용사가 목표 높이에 도달하면 **패배**입니다.

**핵심 기술 축:**

1. **ML-Agents PPO 학습 + ONNX 런타임 추론** — 고정 패턴 AI가 아닌 관측 기반 회피·상승  
2. **휴리스틱 스포너 봇** — Self-play 대신 의도적 스폰 패턴으로 학습 환경 구성  
3. **FSM·동적 맵·3종 장애물·UI** — 상태 머신, `MapGenerator`, 쿨다운 스킬바, Height Bar  
4. **ScriptableObject Config** — 이동·보상·장애물·스포너 수치를 `Assets/5. Data/` SO로 분리, yaml과 역할 분담

**참고 게임:** Donkey Kong(역할 반전), 앵그리버드(사전 궤적), 낙하물 피하기(회피 타이밍)

### 2-0. ScriptableObject 기반 Config (데이터 관리)

튜닝 값·밸런스·학습 보상 계수를 C# 상수로 두지 않고 **ScriptableObject(SO)** 로 분리했습니다. Inspector에서 에셋만 교체·복제하면 레벨·학습 단계별 설정을 바꿀 수 있고, `climber.yaml`(학습 하이퍼파라미터)과 역할이 겹치지 않습니다.

| SO | 경로(예) | 담당 데이터 |
|----|----------|-------------|
| `ClimberMovementConfig` | `Assets/5. Data/Climber/` | 이동·점프·중력·HP·지상 판정 BoxCast |
| `ClimberVer2RewardWeightConfig` | `Assets/5. Data/Climber/` | RL 보상 가중치·정체 시간·착지 Δ |
| `ObstacleTuningConfig` | `Assets/5. Data/Obstacles/` | 3종 속도·쿨다운·Cast 반경·레이어 |
| `SpawnerPatternConfig` | `Assets/5. Data/Obstacles/` | 스폰 간격·리드 조준·커리큘럼 on/off |
| `ObstacleSpawnCooldowns` | (씬/프리팹 참조) | 플레이어 스킬 쿨다운 UI 연동 |

**설계 원칙**

- **코드 = 규칙**, **SO = 수치** — `FallSpeed`, `RollSpeed` 등은 SO getter만 참조.
- **학습 yaml ≠ 게임 SO** — PPO `learning_rate`는 yaml, `PlatformLandingReward`는 SO.
- **에셋 복제로 커리큘럼** — `ClimberVer2RewardWeightConfig 1`, `SpawnerPatternConfig`(Faller-only) 등 학습 단계별 SO 스왑.

**첨부 코드** — `ObstacleTuningConfig.cs` · 3종 튜닝 + 쿨다운 일원화

```csharp
[CreateAssetMenu(fileName = "ObstacleTuningConfig", menuName = "GPE/Obstacles/Tuning Config")]
public sealed class ObstacleTuningConfig : ScriptableObject
{
    [SerializeField] private FallerTuning _faller = new();
    [SerializeField] private BouncerTuning _bouncer = new();
    [SerializeField] private RollerTuning _roller = new();

    public FallerTuning Faller => _faller;
    public BouncerTuning Bouncer => _bouncer;
    public RollerTuning Roller => _roller;

    public float GetSpawnCooldown(ObstacleKind kind) => kind switch
    {
        ObstacleKind.Faller => _faller.SpawnCooldownSeconds,
        ObstacleKind.Bouncer => _bouncer.SpawnCooldownSeconds,
        ObstacleKind.Roller => _roller.SpawnCooldownSeconds,
        _ => 0f
    };
}
```

**서술 예시:** 장애물·클라이머·스포너가 각각 다른 SO를 주입받아, 동일 코드로 Lv1~3·학습 씬·플레이 씬을 운영합니다. 리포트에 **`Assets/5. Data/` 폴더 구조 스크린샷** 1장을 넣으면 데이터 주도 설계가 한눈에 보입니다.

### 2-1. [핵심] ML 관측 → 정책 → FSM 실행 파이프라인

**흐름:** `CollectObservations`(8차원 + Ray 센서) → ONNX/PPO 정책 → `WriteDiscreteActionMask`(지상 점프·스턴 제한) → `OnActionReceived` → `ClimberStateMachine.FixedTick` → `ClimberMotor`

**첨부 코드 A** — 8차원 벡터 관측 (`CollectObservations`)

```csharp
// EnemyAgentVer2.cs — stageSpan·moveSpeed·jumpSpeed로 정규화
public override void CollectObservations(VectorSensor sensor)
{
    _groundChecker.Refresh();

    float moveSpeed = _config.MoveSpeed;
    float jumpSpeed = _config.JumpVelocity;
    var agentPosition = (Vector2)transform.position;
    var goalPosition = (Vector2)_goalPoint.position;
    var toGoal = goalPosition - agentPosition;
    float span = _stageSpan;

    sensor.AddObservation(Mathf.Clamp(toGoal.x / span, -1f, 1f));
    sensor.AddObservation(Mathf.Clamp(toGoal.y / span, -1f, 1f));

    var velocity = _rigidbody.linearVelocity;
    sensor.AddObservation(Mathf.Clamp(velocity.x / moveSpeed, -1f, 1f));
    sensor.AddObservation(Mathf.Clamp(velocity.y / jumpSpeed, -1f, 1f));
    sensor.AddObservation(Mathf.Clamp01(toGoal.magnitude / span));

    float lavaDistance = _risingLava.SurfaceY - agentPosition.y;
    sensor.AddObservation(Mathf.Clamp(lavaDistance / span, -1f, 1f));

    bool canJump = _groundChecker.IsGrounded && _motor.CanJump;
    sensor.AddObservation(canJump ? 1f : 0f);
    sensor.AddObservation((float)_health / MaxHealth);
}
```

**첨부 코드 B** — 액션 마스킹 (지상 1회 점프·피격 스턴)

```csharp
public override void WriteDiscreteActionMask(IDiscreteActionMask actionMask)
{
    _groundChecker.Refresh();
    bool inHitStun = _stateMachine.CurrentId == ClimberStateId.HitStun;

    if (inHitStun)
    {
        actionMask.SetActionEnabled(HorizontalBranch, ActionLeft, false);
        actionMask.SetActionEnabled(HorizontalBranch, ActionRight, false);
    }

    bool canJump = !inHitStun && _groundChecker.IsGrounded && _motor.CanJump;
    actionMask.SetActionEnabled(JumpBranch, JumpAction, canJump);
}
```

**첨부 코드 C** — FSM 상태 전이 (`ClimberStateMachine.cs`)

```csharp
public void ChangeState(ClimberStateId nextId)
{
    if (CurrentId == nextId)
        return;

    _current.Exit(_context);
    CurrentId = nextId;
    _current = _states[nextId];
    _current.Enter(_context);
}

public void FixedTick(ClimberMoveInput input) => _current.FixedTick(_context, input);
```

**서술 예시:** Ray Perception은 자식 Sensor로 장애물·발판을 추가 관측하고, 벡터 8차원은 목표·속도·용암·점프 가능·체력을 stage span 기준으로 정규화합니다. `ClimberMovementConfig` SO의 `MoveSpeed`·`JumpVelocity`로 관측을 정규화하므로, SO만 바꿔도 관측 스케일이 코드 수정 없이 맞춰집니다.

### 2-2. [핵심] 장애물 3종 — 물리 구현 방식

3종 모두 **`ObstacleBase` 공통 골격** 위에 종류별 `OnFixedTick`만 다릅니다. Rigidbody2D **Dynamic + 충돌체 반사**가 아니라, **Kinematic + 수동 이동 + CircleCast/BoxCast 선행 검사** 패턴을 씁니다. 벽·발판 레이어와 속도는 `ObstacleTuningConfig` SO에서 읽습니다.

| | Faller | Bouncer | Roller |
|---|--------|---------|--------|
| **이동 모델** | 등속 수직 낙하 | 등속 2D 비행 | 공중: 중력 낙하 / 지상: 등속 구름 |
| **환경 상호작용** | 없음 (벽·발판 무시) | 좌우 **벽** CircleCast 반사 | **발판** 착지 + 벽에서 roll 방향 반전 |
| **Rigidbody** | Kinematic, `MovePosition` | Kinematic, `MovePosition` | Kinematic, 위치 직접 갱신 |
| **피격** | Trigger → `IClimberAgent.ApplyHit()` | 동일 | 동일 |

**공통 (`ObstacleBase`)** — Trigger 전용 피격, Kinematic RB, SO 튜닝

```csharp
// ObstacleBase.cs — body collider 없이 Trigger + 수동 이동
_rigidbody.bodyType = RigidbodyType2D.Kinematic;
_rigidbody.gravityScale = 0f;
_rigidbody.collisionDetectionMode = CollisionDetectionMode2D.Continuous;

private void OnTriggerEnter2D(Collider2D other)
{
    if (!other.TryGetComponent(out IClimberAgent climber))
        return;
    climber.ApplyHit();
    _hitConsumed = true;
    ReleaseToPool();
}
```

#### Faller — 등속 낙하 (Physics2D 중력 미사용)

**흐름:** 스폰 → 매 FixedUpdate마다 `y -= FallSpeed × Δt` → `Rigidbody.MovePosition`

```csharp
// FallerObstacle.cs — Trigger only, walls/platforms ignored
protected override void OnFixedTick(float deltaTime)
{
    float speed = Tuning.Faller.FallSpeed;
    var position = (Vector2)transform.position;
    position.y -= speed * deltaTime;
    Rigidbody.MovePosition(position);
    Rigidbody.linearVelocity = new Vector2(0f, -speed);
}
```

**서술:** 가장 단순한 **1축 kinematic**. ML-Agent는 Ray Perception + 반응형 dodge로 대응.

#### Bouncer — 등속 비행 + CircleCast 벽 반사

**흐름:** 발사 방향(플레이어 드래그 or SO 기본각) × `LaunchSpeed` → 이동 전 **CircleCast** → 좌우 벽(`normal.x` 큼)이면 **X 방향 반전** + `WallBounceDamping`

```csharp
// BouncerObstacle.cs
protected override void OnFixedTick(float deltaTime)
{
    var displacement = _direction * _speed * deltaTime;
    TryApplyMoveWithWallBounce(ref position, displacement, tuning);
    ApplyPosition(position);
}

private void TryApplyMoveWithWallBounce(ref Vector2 position, Vector2 displacement, ...)
{
    var hit = Physics2D.CircleCast(position, tuning.CastRadius,
        displacement / distance, distance, tuning.WallLayers);

    if (hit.collider == null || Mathf.Abs(hit.normal.x) < 0.5f)
    {
        position += displacement;
        return;
    }

    _direction.x = Mathf.Abs(_direction.x) * Mathf.Sign(hit.normal.x);
    _direction = _direction.normalized;
    _speed *= tuning.WallBounceDamping;
    position = (Vector2)hit.point + hit.normal * (tuning.CastRadius + tuning.SurfaceSkin);
}
```

**서술:** Roller와 **동일한 CircleCast 벽 처리**를 재사용. 플레이어 `ClampDownwardFromHorizontal`과 학습 봇 각도 샘플링이 같은 SO 각도 제한을 공유.

#### Roller — 발판 착지 후 목표 방향 구름 + 벽 반전

**흐름:** 공중 → `gravity × GravityScale` 낙하 → **CircleCast 아래**로 발판 감지 → 착지 시 **클라이머 X** 쪽으로 roll 방향 결정 → 지상에서는 `RollSpeed` 등속 + 벽 hit 시 `_rollDirection` 부호 반전

```csharp
// RollerObstacle.cs — landing picks roll direction toward climber X
protected override void OnFixedTick(float deltaTime)
{
    if (TryGetPlatformHit(out var hit))
    {
        if (!_wasOnPlatform)
            _rollDirection = ResolveRollDirectionAtLanding();

        _velocity.x = _rollDirection * tuning.RollSpeed;
        _velocity.y = 0f;
        TryApplyHorizontalMove(ref position, deltaTime, radius);  // wall CircleCast
        position.y = hit.point.y + radius;
    }
    else
    {
        _velocity.y += Physics2D.gravity.y * tuning.GravityScale * deltaTime;
        position.y += _velocity.y * deltaTime;
    }
}

private int ResolveRollDirectionAtLanding()
{
    float delta = GetClimberWorldXAtLanding() - transform.position.x;
    if (delta > tuning.AimXDeadZone) return 1;
    if (delta < -tuning.AimXDeadZone) return -1;
    return _rollDirection;
}
```

**서술:** Donkey Kong 배럴처럼 **발판을 따라 굴러가며** 클라이머를 추격. Jump 타이밍을 요구하는 3번째 위협 축.

**리포트 캡처:** `04_Faller`, `05_Bouncer`, `06_Roller` + Inspector `ObstacleTuningConfig` SO 1장

### 2-3. [핵심] 휴리스틱 스포너 — 쿨다운 경쟁 + 리드 조준

**흐름:** `SpawnIntervalSeconds`마다 시도 → 패턴 SO에서 활성화된 종류만 후보 → **쿨다운이 가장 긴(=플레이어에게 가장 “아까운”) 종류** 우선 → 속도×`AimLeadSeconds`로 X 조준 → Bouncer는 하향 각도 샘플링

**첨부 코드 A** — 쿨다운 우선순위 선택

```csharp
// HeuristicSpawnerBot.cs — Roller > Bouncer > Faller (쿨다운 길이 기준)
private bool TryPickReadyKindWithLongestCooldown(out ObstacleKind kind)
{
    kind = default;
    float bestCooldown = -1f;
    bool found = false;

    for (int i = 0; i < AllKinds.Length; i++)
    {
        ObstacleKind candidate = AllKinds[i];
        if (!_pattern.IsKindEnabled(candidate))
            continue;
        if (!_spawner.IsReady(candidate))
            continue;

        float cooldown = _spawner.CooldownDuration(candidate);
        if (cooldown <= bestCooldown)
            continue;

        bestCooldown = cooldown;
        kind = candidate;
        found = true;
    }
    return found;
}
```

**첨부 코드 B** — Bouncer 하향 발사 각도 (플레이어와 동일한 어려운 각도)

```csharp
private Vector2 SampleRandomDownwardBouncerDirection()
{
    float tilt = Random.Range(_pattern.BouncerMinDownTiltDegrees,
                              _pattern.BouncerMaxDownTiltDegrees);
    float side = Random.value < 0.5f ? -1f : 1f;
    float angleDeg = 270f + side * tilt;  // 아래(270°) ± 틸트
    float rad = angleDeg * Mathf.Deg2Rad;
    return new Vector2(Mathf.Cos(rad), Mathf.Sin(rad)).normalized;
}
```

**서술 예시:** Self-play 대신 “보스 패턴 테이블”처럼 스폰 봇을 설계했습니다. `SpawnerPatternConfig` SO로 종류 on/off·`AimLeadSeconds`를 바꾸며, `ObstacleTuningConfig.GetSpawnCooldown`과 연동해 쿨다운이 긴 스킬을 우선 사용합니다.

### 2-4. [핵심] 보상 shaping — 착지 상승·하강·정체 패널티

**흐름:** 공중→지상 FSM 전이 시 `TryRewardNewPlatformLanding` → 이전 최고 Y 대비 새 고도면 보상 / 낮은 발판이면 패널티 → 매 decision `ApplyPlatformStallPenalty`로 같은 발판 3초 이상 정체 시 소량 패널티

**첨부 코드 A** — 착지 보상·하강 패널티

```csharp
// EnemyAgentVer2.cs — Grounded 진입 시 호출
private void TryRewardNewPlatformLanding()
{
    float landingY = transform.position.y;
    float minDelta = _rewardWeights.MinLandingHeightDelta;

    if (landingY > _bestY + minDelta)
    {
        _bestY = landingY;
        _lastLandingY = landingY;
        AddReward(_rewardWeights.PlatformLandingReward);
        _platformLandingsThisEpisode++;
    }
    else if (landingY < _lastLandingY - minDelta)
    {
        _lastLandingY = landingY;
        AddReward(_rewardWeights.PlatformLandingDownPenalty);
    }
    // ...
}
```

**첨부 코드 B** — 정체 패널티 (벽 비비기·제자리 점프 억제)

```csharp
private void ApplyPlatformStallPenalty()
{
    if (!_groundChecker.IsGrounded)
        return;

    var platform = _groundChecker.CurrentPlatform;
    int platformId = platform.GetInstanceID();

    if (platformId != _stallPlatformInstanceId)
    {
        _stallPlatformInstanceId = platformId;
        _platformStallElapsed = 0f;
        return;
    }

    _platformStallElapsed += Time.time - _lastPlatformStallSampleTime;

    if (_platformStallElapsed >= _rewardWeights.PlatformStallTimeSeconds)
        AddReward(_rewardWeights.PlatformStallPenaltyPerDecision);
}
```

**서술 예시:** `ClimberVer2RewardWeightConfig` SO로 보상 계수를 분리해, Faller 도입 후 “왼쪽 이동·점프만 반복”하는 local optimum을 **정체 패널티**와 **피격 패널티**로 깨도록 설계했습니다. yaml의 extrinsic γ=0.99와 역할을 나누어, 게임 밸런스는 SO·코드, 학습 하이퍼파라미터는 `climber.yaml`에서 각각 튜닝합니다.

**첨부 코드** — `MapGenerator.cs`

```csharp
public void RegenerateMap()
{
    ClearSpawned();
    currentTopPosition = transform.position + Vector3.up * offsetY;
    GenerateMap();
}

private void GenerateMap()
{
    int lastIndex = -1;
    for (int i = 0; i < mapLength; i++)
    {
        int randomIndex;
        do { randomIndex = Random.Range(0, templates.Length); }
        while (randomIndex == lastIndex);
        lastIndex = randomIndex;
        SpawnTemplate(templates[randomIndex]);
    }
    SpawnTemplate(endTemplate);  // EndTemplateWorldY 저장
}
```

### 4-1. [필수] ML Agent Behavior Parameters 설정

#### Inspector 기록 표 (학습 씬 기준 — 팀이 실제 값 확인 후 숫자 보완)

| Take Actions Between Decisions | **true** | |

### 4-2. [필수] Training Configuration File (`climber.yaml`)

**경로:** `Assets/4. ML/Configs/climber.yaml`

```yaml
behaviors:
  ClimberAgent:
    trainer_type: ppo
    hyperparameters:
      batch_size: 128
      buffer_size: 10240
      learning_rate: 3.0e-4
      beta: 3.0e-3
      epsilon: 0.2
      lambd: 0.95
      num_epoch: 4
      learning_rate_schedule: linear
    network_settings:
      normalize: false
      hidden_units: 256
      num_layers: 2
    reward_signals:
      extrinsic:
        gamma: 0.99
        strength: 1.0
    keep_checkpoints: 6
    checkpoint_interval: 100000
    max_steps: 10000000
    time_horizon: 128
    summary_freq: 10000
```

| 항목 | 설명 포인트 |
|------|-------------|
| `ppo` | on-policy, 이산 액션에 안정적 |
| `normalize: false` | resume 시 normalizer 키 불일치 주의 |
| `checkpoint_interval: 100000` | Lv1/Lv2/Lv3 ONNX dial |
| `time_horizon: 128` | 회피 시퀀스 길이 |

```bash
mlagents-learn Assets/4. ML/Configs/climber.yaml --run-id=ClimberRun
mlagents-learn Assets/4. ML/Configs/climber.yaml --run-id=ClimberRun_Faller --initialize-from=ClimberRun
```
